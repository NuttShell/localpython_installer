# Python Embed Installer

Python Embed Installer - скрипты для Windows, которые разворачивают рядом с собой
изолированную embeddable-сборку Python (без системной установки, без изменения `PATH`),
ставят в неё `pip` и нужные пакеты. Есть две версии одного и того же алгоритма — консольная
и с графическим интерфейсом.

## Что делает скрипт в обеих версиях:

1. Проверяет соединение с `python.org`.
2. Забирает с `https://www.python.org/ftp/python/` список доступных embeddable-сборок
   (`python-X.Y.Z-embed-amd64.zip` / `-win32.zip`).
3. Даёт выбрать версию и архитектуру (или берёт их из конфига — см. таблицу ниже).
4. Скачивает и распаковывает ZIP в папку `python/` рядом со скриптом.
5. Ставит `pip` (через `get-pip.py`, при неудаче — фолбэком через wheel с PyPI).
6. Ставит пакеты.
7. Удаляет временную папку `download/`.

Результат — папка `python/` рядом со скриптом с рабочим `python.exe`, `pip` и установленными
пакетами, готовая к использованию.

## Файлы

| Файл | Обязателен | Назначение |
|---|---|---|
| `get_con.cmd` | да | консольная версия |
| `get_win.cmd` | да | версия с графическим интерфейсом |
| `pyconfig.json` | нет | версия/архитектура Python для **консольной** версии (см. ниже) |
| `requirements.txt` | нет | список пакетов — для **обеих** версий (см. ниже) |
| `bootstrap.ps1` | нет | загрузчик для удалённого запуска `get_con.cmd` одной командой (`irm ... \| iex`), см. «Использование» |

Версию и архитектуру для консольной версии можно также задать ключами командной строки
(`-PyVer`/`-Arch`) — без файла вообще, подробности в разделе «Использование».

## Сравнение версий

| | `get_con.cmd` | `get_win.cmd` |
|---|---|---|
| **Интерфейс** | текстовые меню в консоли | окно WinForms: заголовок, статус, прогресс-бар, детали |
| **Окно консоли** | видимое на всё время работы | скрывается (`ShowWindow`), пользователь видит только GUI-окно |
| **Для кого** | подготовленный пользователь, автоматизация, CI | человек без опыта работы с консолью |
| **Выбор версии/архитектуры Python** | интерактивное меню (список версий → список архитектур), либо ключи командной строки `-PyVer`/`-Arch`, либо файл `pyconfig.json` (приоритет: ключи → `pyconfig.json` → интерактив) | только интерактивный список (`ListBox`) с готовыми парами `версия [архитектура]` |
| **Запуск из другого скрипта / тихий режим** | да — `get_con.cmd -PyVer 3.14.1 -Arch amd64`, без диалога; с `pyconfig.json` без ключей — тоже без диалога, если сборка есть на python.org; также поддерживается запуск одной командой без скачивания файла (`irm ... \| iex` через `bootstrap.ps1`) | нет, GUI всегда ждёт клика пользователя |
| **Если запрошенная версия/архитектура (ключи или `pyconfig.json`) не найдена на python.org** | предлагает выбор: `[S]elect version manually` / `[C]ancel`; при ручном выборе результат перезаписывается в `pyconfig.json` | — (ни ключей, ни конфига в GUI нет) |
| **Список пакетов по умолчанию** (без `requirements.txt`) | `pyinstaller` (константа `$DEFAULT_PACKAGES`) | `pyinstaller` (константа `$DEFAULT_PACKAGES`) |
| **Кастомизация списка пакетов** | `requirements.txt` рядом со скриптом (обычный pip-формат: версии, markers, комментарии `#`) | то же самое — `requirements.txt` рядом со скриптом |
| **Прогресс скачивания** | процент и MB прямо в консоли (обновляется по мере чтения потока) | `ProgressBar` + текст с процентом и MB, скачивание асинхронное |
| **Индикация происходящего во время pip/python** | только финальный статус (успех/провал) | построчный разбор stdout/stderr процесса, ключевые строки (`Collecting`, `Installing`, ошибки) показываются в панели деталей |
| **Детали ошибки pip/python при сбое** | *не показываются* — известное ограничение, см. ниже | показывается конкретная строка ошибки |
| **Всплывающие сообщения об ошибках** | текст в консоли | `MessageBox` |
| **Что видно по завершении** | текстовый блок `COMPLETE` в консоли, ожидание нажатия клавиши | обновлённая GUI-панель с итогами + кнопка **Close** |

## Использование

### Консольная версия (`get_con.cmd`)

Запуск без дополнительных параметров — спросит версию и архитектуру Python интерактивно,
затем поставит `pip` и пакеты по умолчанию (`pyinstaller`). Если рядом со скриптом есть свой
список (файл `requirements.txt`), будут установлены пакеты, перечисленные в этом файле 
(подробнее — в разделе «Список устанавливаемых пакетов» ниже).

Версию и архитектуру устанавливаемого Python можно задать двумя способами.

**1. Ключи командной строки**:

```bat
get_con.cmd -PyVer 3.14.1 -Arch amd64
```

Это обычный параметр — регистр не важен (`-pyver`, `-ARCH` и т.п. тоже
работают). Указывать нужно оба ключа сразу: если задан только один — скрипт завершится с
ошибкой, не пытаясь угадать второй.

**2. Файл `pyconfig.json`** рядом со скриптом:

```json
{
    "version": "3.12.4",
    "arch": "amd64"
}
```

- `version` — точная версия в формате `X.Y.Z`.
- `arch` — `amd64` или `win32`.

Если заданы и ключи и есть файл `pyconfig.json` — **ключи командной
строки в приоритете**, `pyconfig.json` в этом случае игнорируется.

Поведение (для обоих источников общее):
- ни ключей, ни файла нет → обычный интерактивный выбор;
- источник валиден и такая сборка есть на python.org → используется без вопросов;
- источник валиден, но версии/архитектуры на python.org нет → сообщение об ошибке и выбор:
  `[S]elect version manually` (перейти к интерактивному выбору, а результат — записать обратно
  в `pyconfig.json`, даже если исходный запрос пришёл через ключи) или `[C]ancel` (выйти);
- значение повреждено / не JSON / не хватает полей / неверный формат версии или архитектуры →
  скрипт завершается с явной ошибкой, не трогая интерактив.

**3. Удалённый запуск, без скачивания файла на диск**:

```powershell
irm https://nuttshell.github.io/localpython_installer/bootstrap.ps1 | iex
```

Запускает установку с параметрами по умолчанию (как двойной клик по
`get_con.cmd` без ключей: возьмёт `pyconfig.json`/`requirements.txt` из **текущей** директории
PowerShell, если они там есть, иначе — обычный интерактив).

Папка `python/` в этом сценарии создаётся в текущей директории PowerShell (там, откуда вызвана
команда) — а не «рядом со скриптом», как при локальном запуске, поскольку самого файла на диске
не существует.

### GUI-версия (`get_win.cmd`)

Запускается двойным щелчком. Открывается окно — версия и архитектура Python выбираются из
списка мышкой, дальше всё автоматически.

### Список устанавливаемых пакетов (обе версии)

По умолчанию (без `requirements.txt`) ставится `pyinstaller`.

Чтобы поставить свой набор — положите файл `requirements.txt` рядом с нужным скриптом (для
`get_con.cmd` и `get_win.cmd` — независимо друг от друга, можно использовать разные файлы в
разных папках) в обычном pip-формате:

```
pyinstaller==6.10.0
fonttools>=4.53
# строки с решёткой игнорируются
```

Если файл присутствует и не пуст — ставится он вместо пакетов по умолчанию; иначе — как и
раньше, `pyinstaller`.

## Требования

- Windows 10/11 с PowerShell 5.1 (входит в систему, отдельно ставить не нужно).
- Доступ в интернет к `python.org`, `bootstrap.pypa.io`, `pypi.org` (и к `raw.githubusercontent.com`
  для удалённого запуска через `bootstrap.ps1`).
- Права на запись в папку рядом со скриптом (или в текущую директорию — при удалённом запуске).

## Известные ограничения

- **Консольная версия не показывает детали ошибок pip/python.** Функция `Invoke-Python` в
  `get_con.cmd` запускает процесс через `Start-Process` без перехвата вывода, поэтому при сбое
  установки pip или пакета видно только код завершения, без текста ошибки. В GUI-версии тот же
  сценарий показывает конкретную строку из stderr. Планируется к исправлению.
- `pyconfig.json` поддерживается только консольной версией — осознанное решение: GUI рассчитан
  на пользователя, который не будет вручную редактировать JSON.
