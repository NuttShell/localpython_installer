# Python Embed Installer

Самораспаковывающиеся `.cmd`-скрипты для Windows, которые разворачивают рядом с собой
изолированную embeddable-сборку Python (без системной установки, без изменения `PATH`),
ставят в неё `pip` и нужные пакеты. Есть две версии одного и того же алгоритма — консольная
и с графическим интерфейсом.

## Как это устроено

Каждый `.cmd`-файл — это гибрид: сверху обычный batch-заголовок, ниже (после метки
`REM_PS1_CODE_START`) — тело PowerShell-скрипта. При запуске batch-часть вырезает PowerShell-код
из самого себя, сохраняет во временный `.ps1` во `%TEMP%` и выполняет его с
`-ExecutionPolicy Bypass`. Никаких дополнительных файлов для распространения не нужно —
достаточно одного `.cmd`.

Что делает PowerShell-часть в обеих версиях:

1. Проверяет соединение с `python.org`.
2. Забирает с `https://www.python.org/ftp/python/` список доступных embeddable-сборок
   (`python-X.Y.Z-embed-amd64.zip` / `-win32.zip`).
3. Даёт выбрать версию и архитектуру (или берёт их из конфига — см. таблицу ниже).
4. Скачивает и распаковывает ZIP в папку `python/` рядом со скриптом.
5. Ставит `pip` (через `get-pip.py`, при неудаче — фолбэком через wheel с PyPI).
6. Ставит пакеты.
7. Удаляет временную папку `download/`.

Результат — папка `python/` рядом со скриптом с рабочим `python.exe`, `pip` и установленными
пакетами, готовая к использованию (например, как окружение для сборки PyInstaller-экзешников).

## Файлы

| Файл | Обязателен | Назначение |
|---|---|---|
| `get_con.cmd` | да | консольная версия |
| `get_win.cmd` | да | версия с графическим интерфейсом |
| `pyconfig.json` | нет | версия/архитектура Python для **консольной** версии (см. ниже) |
| `requirements.txt` | нет | список пакетов для **GUI**-версии (см. ниже) |

## Сравнение версий

| | `get_con.cmd` | `get_win.cmd` |
|---|---|---|
| **Интерфейс** | текстовые меню в консоли | окно WinForms: заголовок, статус, прогресс-бар, детали |
| **Окно консоли** | видимое на всё время работы | скрывается (`ShowWindow`), пользователь видит только GUI-окно |
| **Для кого** | подготовленный пользователь, автоматизация, CI | человек без опыта работы с консолью |
| **Выбор версии/архитектуры Python** | интерактивное меню (список версий → список архитектур), либо задаётся файлом `pyconfig.json` | только интерактивный список (`ListBox`) с готовыми парами `версия [архитектура]` |
| **Безголовый / полу-автоматический запуск** | частично — при корректном `pyconfig.json` шаг выбора версии пропускается | нет, GUI всегда ждёт клика пользователя |
| **Если версия из `pyconfig.json` не найдена на python.org** | предлагает выбор: `[S]elect version manually` / `[C]ancel`; при ручном выборе перезаписывает `pyconfig.json` | — (конфига нет в принципе) |
| **Список пакетов по умолчанию** (без доп. файла) | жёстко задан в коде: `pyinstaller`, `fonttools` | `pyinstaller`, `fonttools` (то же самое, но задано отдельной константой) |
| **Кастомизация списка пакетов** | нет — только правка кода скрипта | `requirements.txt` рядом со скриптом (обычный pip-формат, поддерживает версии, markers и т.д.) |
| **Прогресс скачивания** | процент и MB прямо в консоли (обновляется по мере чтения потока) | `ProgressBar` + текст с процентом и MB, скачивание асинхронное |
| **Индикация происходящего во время pip/python** | только финальный статус (успех/провал) | построчный разбор stdout/stderr процесса, ключевые строки (`Collecting`, `Installing`, ошибки) показываются в панели деталей |
| **Детали ошибки pip/python при сбое** | *не показываются* — известное ограничение, см. ниже | показывается конкретная строка ошибки |
| **Всплывающие сообщения об ошибках** | текст в консоли | `MessageBox` |
| **Что видно по завершении** | текстовый блок `COMPLETE` в консоли, ожидание нажатия клавиши | обновлённая GUI-панель с итогами + кнопка **Close** |

## Использование

### Консольная версия (`get_con.cmd`)

Запускается двойным щелчком или из `cmd`/терминала. Без дополнительных файлов — спросит версию
и архитектуру Python интерактивно, затем поставит `pip`, `pyinstaller` и `fonttools`.

Чтобы задать версию и архитектуру заранее (без диалога), положите рядом со скриптом
`pyconfig.json`:

```json
{
    "version": "3.12.4",
    "arch": "amd64"
}
```

- `version` — точная версия в формате `X.Y.Z`.
- `arch` — `amd64` или `win32`.

Поведение:
- файла нет → обычный интерактивный выбор;
- файл валиден и такая сборка есть на python.org → используется без вопросов;
- файл валиден, но версии/архитектуры на python.org нет → сообщение об ошибке и выбор:
  `[S]elect version manually` (перейти к интерактивному выбору, а результат — записать обратно
  в `pyconfig.json`) или `[C]ancel` (выйти);
- файл повреждён / не JSON / не хватает полей / неверный формат версии или архитектуры → скрипт
  завершается с явной ошибкой, не трогая интерактив.

### GUI-версия (`get_win.cmd`)

Запускается двойным щелчком. Открывается окно — версия и архитектура Python выбираются из
списка мышкой, дальше всё автоматически, с прогресс-баром.

Список пакетов по умолчанию — `pyinstaller` и `fonttools`. Чтобы поставить свой набор, положите
рядом со скриптом `requirements.txt` в обычном pip-формате:

```
pyinstaller==6.10.0
fonttools>=4.53
# строки с решёткой игнорируются
```

Если файл присутствует и не пуст — ставится он вместо пакетов по умолчанию.

## Требования

- Windows 10/11 с PowerShell 5.1 (входит в систему, отдельно ставить не нужно).
- Доступ в интернет к `python.org`, `bootstrap.pypa.io`, `pypi.org`.
- Права на запись в папку рядом со скриптом (туда распаковывается `python/`).

## Известные ограничения

- **Консольная версия не показывает детали ошибок pip/python.** Функция `Invoke-Python` в
  `get_con.cmd` запускает процесс через `Start-Process` без перехвата вывода, поэтому при сбое
  установки pip или пакета видно только код завершения, без текста ошибки. В GUI-версии тот же
  сценарий показывает конкретную строку из stderr. Планируется к исправлению.
- `pyconfig.json` поддерживается только консольной версией — осознанное решение: GUI рассчитан
  на пользователя, который не будет вручную редактировать JSON.

## Версионирование

Версия скрипта — дата последнего изменения в формате `YY.MMDD` (например, `26.0730` —
30 июля 2026). Хранится в переменной `version` в начале каждого `.cmd`-файла.
